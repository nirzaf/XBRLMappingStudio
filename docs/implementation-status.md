| MAP04 | Partially implemented | `DecimalDomain` bounds numeric lexemes to the CLR decimal limit of 29 significant digits and 28 fractional places before parsing, preventing silent `decimal.TryParse` rounding; explicit-culture grouping must follow that culture's group sizes and cannot occur in the fractional part. `ParseDecimal` uses an explicit culture and accepts one balanced accounting-parentheses pair as a negative number while rejecting malformed or explicitly double-signed forms; invariant numeric parsing remains stricter. Decimal string formatting is invariant; Scale, ChangeSign, Round and Ratio preserve explicit nil separately from missing. Scale factors use the bounded invariant decimal parser. Half-even, half-up and truncate modes reject digit counts above CLR's 0..28 decimal scale and skip intermediate scaling when the requested precision already matches the value; Round validates its mode and scale before propagating missing or nil input. Scale rejects both nonzero underflow and any product CLR decimal arithmetic would silently round. Ratio allows unconfigured quotients only when an exact decimal round trip proves no division rounding occurred; inexact quotients block with MAP008. Both `digits` and `mode` may be supplied to round an exact integer-rational quotient directly to the declared 0..28 scale using HalfUp, HalfEven or Truncate; partial or invalid configuration blocks with MAP018 before missing/nil propagation. Profile-specific precision/rounding policies remain open. |
