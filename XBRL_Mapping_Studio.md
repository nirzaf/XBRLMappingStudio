# XBRL Mapping Studio

## Architecture and atomic implementation specification

**Decision record · 3 November 2026 · Proposed architecture**

**Use Avalonia UI, .NET 10 LTS, Arelle, and Microsoft.Extensions.AI.** Build an offline-capable desktop designer with a portable C# execution engine. Run Arelle as a local Python worker. Use AI to draft mappings that an analyst can inspect, correct and approve.

**Delivery context.** The developer works on a Mac mini. This specification assumes Windows x64 is the first customer release, with native macOS development from day one. Qualify a macOS customer release and Linux distributions separately when required. Confirm the Mac mini’s CPU before selecting its native build. The first filing authority, production taxonomy, model provider, customer hardware floor, and data-residency agreement are open decisions.

**Evidence status.** Framework behavior, supported interfaces, package metadata and licensing claims are drawn from the primary sources linked beside each decision. Component designs, target thresholds, fixtures and acceptance criteria are proposals. No application repository, customer workbook, approved taxonomy, Windows benchmark logs, or implementation was supplied. None of the benchmark checkboxes is treated as an executed result.

## 1. Product boundary and decisions

The primary user is a reporting analyst. A successful workflow starts with a workbook, file or database query and ends with a validated report whose individual facts can be traced to their source. The same saved mapping must run unattended. An analyst importing XBRL into a database or spreadsheet authors a separate mapping whenever the transformation loses information. An aggregate financial fact cannot reconstruct the ledger entries from which it was calculated.

| Requested capability | Product commitment | First evidence |
|---|---|---|
| Drag-and-drop mapping and visual functions | Source schema tree, searchable taxonomy, typed ports, graph editing, reusable functions, live sample and errors linked to the graph | A user builds, corrects, saves and reopens a mapping without editing the project file. |
| Generate XBRL from back-end data | Read Excel or a database, transform records, bind fact aspects, serialize and validate under a named profile | Independent expected facts match the reopened deliverable. |
| Use a taxonomy as a source or target | Use its concepts and relationships to interpret an input instance or construct an output instance | Both directions preserve the supported aspects, values, occurrences and source identity. |
| Visual XBRL reports | Review financial facts in a presentation-oriented view, with periods, units, dimensions, accuracy and evidence visible | A reviewer can explain a displayed total and inspect its inputs. Formal iXBRL layout, extensions and filing packages are separate profile capabilities. |
| Excel, database, XML, JSON, CSV, PDF | Use explicit source and target capabilities per format. Treat PDF as an input requiring extraction and review | Each advertised direction and supported platform has a round-trip or one-way oracle. |
| Automatic mapping assistance | Retrieve suitable candidates, propose transformations, expose uncertainty, apply reviewed changes | Approved mappings execute with AI disconnected. Suggestions cannot publish a report or write to a target database. |
| High-performance unattended runs | Execute the same graph in a CLI with cancellation, diagnostics, job identity and controlled publication | Batch and desktop yield semantically equivalent output. Compare resource use on named hardware. |

Altova's examples are a functional reference for this scope. The proposed runner executes Studio's own project format. Interoperability with Altova mapping files or its compiled server format requires a separately specified import or integration project. [Altova XBRL mapping](https://www.altova.com/mapforce/xbrl-mapping) · [Altova worked examples](https://www.altova.com/manual/Mapforce/mapforceenterprise/mff_xbrl_examples.html)

## 2. Runtime architecture and trust boundaries

| Runtime boundary | Owns | Allowed interaction |
|---|---|---|
| Desktop process | Avalonia views, editor commands, sampled previews, selection and review | Calls application services directly. Expensive operations are cancellable and off the UI thread. The UI never holds an active database transaction while waiting for user input. |
| Portable application and mapping libraries | Project schema, graph validation, plans, execution, source lineage, job results and publication policy | Both CLI and desktop call these libraries. Domain types have no references to Avalonia, provider SDKs, Python objects, disk layouts or secrets. |
| Adapter layer | Schema introspection, reading, sampling, output preparation and transactional/atomic publication | Opens only sources/targets designated by the project and authorized by the host. Returns typed data or diagnostics, with stable locators for sources. |
| Arelle worker process | Loaded taxonomy, report models, serialization conversion, validation, structured diagnostics | Local private IPC and per-job artifacts. The host starts the known bundled executable and monitors it. The worker receives no model or database credentials. |
| AI integration | Local retrieval, optional inference, proposal validation and explicit review | Receives a bounded data projection. Returns drafts. Only an authorized edit command applies an accepted draft. |
| CLI process | Headless argument validation, locking, observability, cancellation and exit outcomes | Uses the same libraries and approved mappings. Output goes only to declared destinations. Start with the host scheduler. A hosted job service is a later deployment choice. |

**Process protocol.** Use a local child process with UTF-8 framed messages over standard streams. Reserve standard output for protocol traffic and standard error for bounded, sanitized diagnostics. Negotiate protocol version, engine version and capabilities at startup. Each request carries an operation ID, job ID, profile digest, deadline and workspace-scoped artifact handles. Responses distinguish success, domain failure, incomplete validation, cancellation and worker crash. Page taxonomy results and transfer reports by file handle or controlled workspace path. Avoid a process call per cell. Validate protocol shape and byte limits. Bind handles to their job, canonicalize paths including symlinks, and prohibit arbitrary executable paths or plugins from project files. Process isolation improves fault recovery. Actual confinement of untrusted content requires tested OS controls.

**Project and revision contract.** Keep stable IDs for nodes, ports, edges, functions, connectors and source bindings. Store file locators relative to an approved workspace when portable. Supply environment-specific connection profiles and credentials at execution. Persist a schema version, function-catalog version, connector capability requirements, taxonomy/profile digests, accepted mappings and layout. Maintain a semantic revision independent of layout positions and a separate full-document save generation that includes layout. Stage a temporary sibling file and verify it. Under an exclusive per-project writer lock, re-read the current generation, compare it with the editor’s expected generation, then replace on the same filesystem. Locking and atomic replacement must be proven on any network filesystem offered as a shared workspace. Preserve the last readable project on failure. Unknown future formats open read-only with an explanation. Migrations operate on a copy, retain the original and produce a change report.

**Approval and data ownership.** A project can contain a draft while an earlier semantic revision remains approved for automation. Editing an executable value, input binding, taxonomy profile or reusable function creates a new draft. Pure layout edits retain semantic approval. Record who accepted which revision, when and under which authority. Resolve credentials per deployment. A changed source schema, unit header or required period binding triggers preflight even for a previously approved project.

**Execution and reproducibility.** At start, freeze the project revision, parameters, locale, fiscal calendar, source identities and ruleset. Record file hashes or a database snapshot/extract identifier. If a live database cannot provide a replayable snapshot, mark the read as non-replayable and retain an authorized immutable extract when exact reproduction is required. Use a read-only sample for previews and label sampled aggregates as partial. Full and preview runs share a compiler. Only the input selection changes. Every output fact or row can cite its contributing source occurrences and graph steps. For large aggregations, persist a bounded or paged lineage reference plus counts and integrity metadata instead of storing huge lists on screen.

**Diagnostic contract.** Use stable product codes, subsystem, severity, stage, blocking status, operation ID and rule identifier. Add source references and mapping node/port when available. Keep full technical evidence in a controlled support bundle. Provide actionable messages such as “Revenue requires a start and end date. Supply the missing start date.” A mapping that can be saved as a draft may still be ineligible for execution.

## 3. Mapping language and deterministic execution

The portable mapping model is the product's long-lived asset. Describe data with records, fields, ordered collections, scalar types, nullable values, and source cardinality. A function accepts a declared shape and emits a declared shape. Include signed exact numeric values, dates, instants, strings, booleans, identifiers and qualified names. Distinguish a missing source field, blank text, an explicit nil and numeric zero. Reject an unsupported precision or a conversion requiring an undefined culture, scale or rounding policy. SQL Server can store higher precision than the CLR decimal type. Detect the mismatch before a value is narrowed. [SQL Server data type mappings](https://learn.microsoft.com/en-us/sql/connect/ado-net/sql-server-data-type-mappings)

For the first profile, qualify a bounded exact-decimal domain. Select a documented maximum number of significant digits and fractional scale using the reference taxonomy and source data. Validate incoming lexical numbers and each intermediate operation before narrowing to a CLR type. Standard numeric conversion can round. If exact representation is impossible, keep the original lexical input for evidence and reject the operation or use an explicitly configured rounding function. Exercise just-inside and just-outside limits, division, and scaling overflow. Extend numeric representation only for a demonstrated profile requirement.

Use a directed acyclic graph for the initial catalog. Express repetition with a collection-mapping operator, grouping with explicit keys, and joins with declared cardinality. Report unbound ports, incompatible shapes, cycles, missing context and invalid grouping during preflight. Sequence independent operations using deterministic tie-breaking. Sort explicitly when output order matters. Functions read only explicit inputs. A date, exchange rate, or lookup that changes over time enters as a versioned run parameter or snapshotted source. Define divide-by-zero, overflow, ambiguous dates, missing lookup keys and many-to-many joins as explicit outcomes.

| Function family | Initial behavior | Reliability requirement |
|---|---|---|
| Selection and parsing | Select field, constant, trim, parse number/date, lookup | Declare culture and fallback. Preserve the source text and report ambiguity. |
| Numeric | Multiply by scale, change sign, round, ratio | Declare rounding mode and supported precision. Reporting accuracy is a separate output property. |
| Conditional | Compare, select branch, coalesce, filter | Document missing/nil/zero behavior per operator. |
| Collections | Repeat, group, sum, join | Require keys, declare duplicate or unmatched behavior and enforce configured expansion limits. |
| Fact construction | Bind concept, entity, period, unit, dimensions and accuracy | The inspector exposes required aspects, resolved values and data provenance. |
| Reusable visual functions | Save a typed subgraph with named inputs, outputs and revision | Pin versions at each call site. Disallow recursion initially. Upgrades preview changes before adoption. |

## 4. Source and target adapters

Each adapter declares which operations it supports, including schema inspection, sampling, reading, staged writes, publication, cancellation and source lineage. Mark unsupported operations in the designer before a user starts mapping. Implement the simplest adapter for the first vertical slice. Add a new library only when a supported input or output needs it.

| Data family | Read path | Write path and reliability boundary |
|---|---|---|
| Excel | Discover sheets, tables, named ranges, values, displayed headings and formula/cache state. Select an explicit header row or rectangular template region. | Write a new workbook or an explicitly supported template copy. Stage it, reopen the exact file and reconcile row counts and relevant values. Never overwrite a source workbook implicitly. |
| Ordinary CSV, JSON and XML | Define encoding, delimiter, culture, schema and repeating paths. Preserve namespaces and array multiplicity. Bound input size, row count, parser depth and string length. | Define output shape and order. Reopen the result with an independent fixture assertion. | Database | Discover permitted schema objects, read a parameterized query or selected table, and stream typed records. Advertise the read and write modes supported per vendor. |
| PDF | Read embedded text and coordinates or rasterize an image-only region and use OCR. ### Excel without a desktop Excel dependency

Prefer table and column identities or named ranges when the customer's template offers them. Save a schema fingerprint and expected anchors alongside a positional binding. A moved header, merged region or renamed sheet should prompt for remapping. Retain both raw cell value and displayed unit or period heading where relevant. For a numeric source, do not infer precision from number formatting. Recognize date systems, formula errors, hidden sheets and sign conventions. Specify whether filtered or hidden rows are included. Treat merged headers as structural metadata and prevent them from multiplying financial rows.

Choose a formula policy per profile. A cached value can be stale even when a file loads successfully. A date stamp alone cannot attest to freshness. The safe paths are an authorized recalculated input from the owner's workflow, an explicitly supported calculation subset with comparison fixtures, or a blocked value requesting review. With missing formula results, report the exact affected cell. Start with ordinary XLSX. Legacy XLS and binary XLSB require separate read adapters. Macro-enabled and encrypted files require an explicit support decision. Never execute workbook macros. Excel’s numeric storage can already have lost precision. Flag long identifiers stored as numbers rather than claiming to recover discarded digits. [ClosedXML formula semantics](https://docs.closedxml.io/en/latest/concepts/formula-calculation.html) · [Excel numeric precision](https://support.microsoft.com/en-us/office/excel-specifications-and-limits-1672b34d-7043-467e-8e27-269d656771c3)

For writes, require a declared insert, update, or upsert policy with an explicit business key and duplicate handling. A multi-dimensional fact key must consider concept, entity, period, unit, language and applicable dimensions plus occurrence identity where duplicates are preserved. A simplistic concept-and-date key can overwrite facts. For unattended writes, record a stable operation key in the destination in the same transaction as the changes, or use an equally proven destination idempotency contract. Bind the operation key to an intent fingerprint covering the approved mapping/profile, source snapshot, parameters, destination and write mode. The same key and fingerprint returns the existing receipt. The same key with a different fingerprint is a conflict. On an ambiguous commit, query the durable receipt before retrying. Without such a mechanism, stop for reconciliation and show exactly what is known. ### PDF extraction and review

Classify the page or region, since one file can contain selectable text, scanned tables and searchable OCR layers. Use PdfPig word positions for digital text. A template identifies anchors, table bounds, header-to-column relationships, year, scale and continuation rules. Store page index, crop box, rotation, normalized bounding box, original text and template revision. Map these back to the displayed page. If both text and image paths detect the same amount, resolve the occurrence once. For scans, use a qualified renderer to generate bounded pixel images, then run OCR with a pinned language pack. Tesseract accepts images. Provide a separate renderer for PDF pages. [PdfPig layout](https://github.com/UglyToad/PdfPig/wiki) · [Tesseract supported input](https://tesseract-ocr.github.io/tessdoc/InputFormats.html)

Give users a side-by-side evidence view. Flag ambiguous year columns, bracketed negatives, missing headings, mixed units and OCR corrections. Persist the reviewed value and the original evidence. A changed layout invalidates the template match until reviewed. Test sensitive failure cases such as a scanned minus sign disappearing while both resulting amounts remain valid currency values. Establish an OCR correction and manual-entry workflow even when the local OCR component is unavailable.

## 5. Taxonomies, report generation and validation

### 5.1 Filing profile and supported formats

Treat a filing profile as an immutable agreement about what constitutes an acceptable deliverable for one collector and reporting cycle. Record the regulator, supported report type, effective dates, release identifier, approved entry point or entry-point set, dependency package digests, output syntax and packaging, applicable validation plugins and settings, severity policy, and manual checks. Preserve the profile selected when a mapping was approved. An upgrade creates a new candidate revision, identifies affected bindings, and requires review before export. Taxonomy packages can remap official URLs to local files. Resolve the entire dependency closure offline and report the exact missing resource when a package is incomplete. [XBRL taxonomy publication guidance](https://www.xbrl.org/guidance/taxonomy-publication/) · [Filing rules checklist](https://www.xbrl.org/guidance/filing-rules-checklist-xbrl-report/)

Begin with an agreed profile whose instance can be represented in the XBRL Open Information Model (OIM). The C# engine produces candidate facts with lineage and creates standard xBRL-JSON for the supported subset. Where the profile requires XML, use Arelle's documented OIM-to-XML operation. In the reverse direction its Save Loadable OIM plugin can export supported reports to JSON or CSV. An ordinary JSON document, CSV file, or spreadsheet still needs a mapping to become an XBRL report. Treat xBRL-CSV metadata and its associated tables as one input. Record the exact OIM specification version and verify supported features against the pinned worker. ### 5.2 Taxonomy metadata and the fact contract

The explorer must distinguish a concept identity from its occurrences in presentation networks. Persist the namespace URI and local name with the profile revision. Search labels, documentation and identifiers across supported languages. Display multiple presentation paths and link roles when relevant. ## 9. Unattended execution, protection and operations

### Job lifecycle and publication

Each invocation identifies a project revision, filing profile where applicable, authorized input bindings, parameters, destination and unique run ID. A separate idempotency key and intent fingerprint identify the business operation and its exact inputs across retries. Desktop, CLI and any future server use the same application entry point. An approved graph can execute under an unattended service identity. Model-generated proposals have no role in that path.

| Phase | Required behavior | Failure and recovery |
|---|---|---|
| Preflight | Resolve versioned dependencies and credentials, verify input and output scopes, check write permission, resource budgets, destination locks and profile compatibility. | Return actionable configuration or mapping errors before running expensive validation or mutating a target. |
| Read and execute | Process bounded batches. Stream rows where possible. Buffer only for operators such as joins, sorting and grouping that need retained state. | Use cancellation tokens and deadline propagation. Cap in-memory and spill budgets, protect temporary files and stop cleanly if either budget is exceeded. |
| Stage and validate | Stage files on the destination filesystem. Validate the exact output bytes or package and record their digest. For a DB sink, stage and reconcile proposed writes before the final transactional operation. | Clean job-owned files on cancellation. Worker crash, timeout, or missing validation checks leaves the job incomplete. Do not interpret a zero process exit code as a clean filing. |
| Publish | Check the run still holds the relevant destination lock or expected prior revision. Publish one validated file/package by atomic same-filesystem replacement where supported. Finalize each DB destination under its certified receipt contract. | A single job targeting multiple files or a file and a DB needs explicit per-target receipts. Use one coherent file package where atomic delivery is required. Otherwise report partial publication and offer reconciliation. |
| Report | Persist run ID, inputs, mapping/profile/tool versions, output digests, diagnostic counts, approval evidence, duration and final destination receipts. | Distinguish confirmed committed, rolled back, incomplete, cancelled and unknown outcomes. Recover unfinalized run journals by verifying output digests or DB receipts before retry. |

**Batch throughput test.** Build a workload from short and long reports, with cold and warm taxonomy loads, streamed input and at least one materializing join or group. Increase independent concurrent jobs from one until the host reaches its resource budget. Record reports/hour, facts/second, median and p95 end-to-end duration, backlog wait, peak RSS/private bytes, spill volume and throttling. Include worker startup and final validation. Choose the worker limit from measured peak memory and the customer’s completion window. Reject configurations that improve throughput by dropping checks or compromising interactive latency.

**CLI contract.** Expose project inspection, preflight, preview-to-a-bounded-sample, execute, validate-an-existing-artifact and inspect-run-result operations. Define stable exit categories for success, succeeded with permitted warnings, invalid mapping/data, incomplete profile/configuration, authorization failure, cancelled, and operational failure. Document codes and retryability. Choose a scheduler-friendly success policy for permitted warnings. Reserve standard output for a machine-readable result when requested, and standard error for diagnostics. Supply credentials by an OS secret reference or the scheduler’s approved secret mechanism. Never require secrets in command arguments or a committed project. A scheduled run must never open an interactive credential or approval dialog.

**Security and data retention.** This baseline is a local, single-workspace application. The operating-system identity and workspace access rules define local access. For managed deployments that require separation of duties, bind approval to an authenticated reviewer, immutable revision and controlled audit store. A self-editable project field is insufficient. Maintain explicit user and scheduler credential scopes. Require least-privileged database roles and independently governed model endpoints. Retain only the evidence needed under the customer’s policy. Store protected financial extracts in access-controlled workspaces, use OS-backed secret storage where available, secure temporary directories, expire them and document the behavior after a power failure. A local application operating as a user cannot guarantee resistance to a malicious administrator. A multi-tenant or remote service would require separately designed tenant isolation, authentication, quotas, and per-tenant evidence storage.

**Distribution and support.** Build and sign per target OS and CPU. On macOS, verify the application bundle and nested executables, signing and notarization. On Linux, define a distribution/architecture/display-backend matrix and verify native libraries. Use real OS jobs for package-level smoke tests. A successful cross-build from macOS is insufficient for Windows UI, driver, or code-signing qualification. [Avalonia platforms](https://docs.avaloniaui.net/docs/supported-platforms) · [.NET deployment](https://learn.microsoft.com/en-us/dotnet/core/deploying/) · [macOS deployment](https://docs.avaloniaui.net/docs/deployment/macos)

**Dependency and content lifecycle.** Pin dependency versions and hashes by release. Classify commercial rights individually for the framework, graph control, OCR assets, chosen AI model and endpoint, validation plugins, datasets and taxonomy packages. IFRS explicitly requires a license for integration of its digital taxonomies into products/services. Treat taxonomy embedding, sending labels to a cloud model, and distributing a search index as separate uses to clear under the applicable agreements. Default to locally held, permissible data while those decisions are open. An engine license does not grant rights to the taxonomy. ## 10. Delivery sequence and release acceptance

Deliver vertical slices. The first engineering milestone is a user on the Mac mini opening an Excel field and seeing the same expected XBRL fact as the Windows CLI, with a deliberately incorrect mapping producing a useful error. It is reasonable to run a Windows graph-control spike and an offline taxonomy spike in parallel. Commit to optional connectors, OCR and a production model only as their qualification stages approach.

| Gate | Scope and accountable roles | Required evidence to advance |
|---|---|---|
| G0 · Product and rights | Product owner, reporting specialist, security/licensing owner | Select a customer reporting use case and example source. Classify data and usage rights. Name the authoritative filing rules, fiscal period, target output, review authority, desktop OS and Windows reference hardware. A synthetic profile unlocks early engineering only. |
| G1 · Technical feasibility | Desktop lead and XBRL lead | Restore the pinned UI stack on the Mac mini and Windows, measure the graph prototype, load the taxonomy offline, emit/reopen one independently checked fact, and collect one expected regulator or synthetic validation error. Record gaps with owners. |
| G2 · Usable reporting slice | Reporting specialist, desktop lead and test lead | Close BASE01–04, MAP01–04, IO01–02, XBR01–05 and XBR07, UI01–05 and OPS01–04 for this slice. | G3 · AI-assisted pilot | Reporting specialist, AI engineer, security owner | AI01–08 and UI06. Freeze and score a held-out corpus. Compare manual, deterministic and model-assisted workflows. ### Mandatory acceptance scenarios

| Scenario | End-to-end case | Observable result |
|---|---|---|
| Financial correctness | The workbook contains current and prior-year revenue plus an instant balance, a QAR-thousands heading, zeros, blanks and two dimensional members. | Reopen exported reports and compare numeric values, periods, dimensions, units, accuracy, entity and occurrence counts against an independently authored oracle. |
| Repeatability and review | Save the graph, disable AI, reopen on another qualified machine and run the same snapshots with the CLI. | Equivalent normalized facts and provenance. Report cosmetic or generated-ID differences separately from semantic differences. A signature or file hash attests to a specific artifact, not cross-serializer equivalence. |
| Human correction | The AI suggests gross revenue for a net-revenue column or a PDF swaps two year headings. | A reviewer corrects the proposal from source evidence. Draft output cannot bypass the required review, and offline rerun preserves the corrected mapping. |
| Profile drift | Upgrade to a taxonomy where an existing concept is retired or the permitted dimension changes. | The prior profile still opens and runs with its own assets. The new revision identifies affected bindings and is blocked until resolved and reviewed. |
| Isolation and failure | Kill Arelle midway, exhaust staging space, cancel an export, and interrupt a DB commit. | The UI remains usable, publishes no unvalidated artifact, distinguishes an ambiguous write, and permits safe retry or reconciliation. |
| Scope claims | Import an unsupported XML construct, a legacy workbook, and a PDF without a reliable extraction region. | Show the specific unsupported or review-required state. Prevent silent semantic loss and preserve source evidence subject to retention policy. |

### Extension gates

The baseline implementation can use a synthetic OIM-compatible profile while collector-specific features are under development. The actual named profile qualifies at XBR09 only after all applicable extension gates. If the first regulator mandates XHTML Inline XBRL, an extension taxonomy, signatures, a specific archive layout or submission APIs, bring the appropriate gate forward **before** committing to the first delivery scope. An XML pipeline that passes internal checks cannot close an iXBRL filing requirement. ### Evidence packet and handoff to an implementation team

For each completed ID, retain the revision, dependency lock identifiers, target OS/CPU, fixture identity and rights, expected behavior, executed checks, actual results, artifacts or trace, reviewer, and limitations. Use a focused unit test for pure transformation rules, integration tests with real adapters and pinned Arelle, and interactive Windows tests for the behaviors that depend on the native desktop. Compare against external conformance samples and a reporting specialist's independently written oracle. Generating expected results from the product itself can conceal systematic errors.

At task start, inspect the actual repository and its instructions. Select one ID with closed prerequisites, name the affected boundary and failing fixture, and keep the change limited to that behavior. At handoff, report the smallest diff, the exact checks run, unresolved environmental limits and the evidence location. For documentation or rights tasks, a reviewed decision or issuer permission is the acceptance artifact. Completion of one connector, profile, or target OS confers no certification on others.

**Remaining owner decisions.** Product selects the first reporting jurisdiction, publication format and supported database families. A reporting specialist signs off expected facts and acceptable duplicate/rounding behavior. Security approves cloud/local data policy, identity, retention, native-binary and taxonomy rights. Engineering chooses the graph package only after the spike and records the workstation floor and benchmark budgets before measurement. These decisions can proceed independently of the initial synthetic, offline development slice.
